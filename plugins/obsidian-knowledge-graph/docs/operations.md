# 운영과 현재 제한

원본은 바이트와 SHA-256을 유지하며 수정본은 새 revision입니다. 등록은 원본·메타데이터만 만들고, 정리는 분리된 요청입니다. read는 기본 4000자·최대 8000자이며 긴 한 줄도 cursor로 이어집니다. 줄 범위와 cursor는 같은 조건으로 재호출합니다.

검색은 별칭·유형·날짜·버전 필터와 카탈로그를 사용합니다. coverage의 미정리·추출 미지원·오래된 요약을 확인합니다. 의미 검색·벡터 DB·자동 원문 이해는 포함하지 않습니다. 사용자 정의 주제는 topic_definitions로 등록하거나 vocabulary.yaml을 편집하고 카탈로그를 재생성합니다.

Git sync는 완료한 이전 미동기화 등록의 파일을 공용 카탈로그와 함께 반영할 수 있습니다. 해당 파일들은 앞선 명시적 등록 요청의 범위입니다. 임의 작업 파일은 포함하지 않습니다. 사람이 stage한 변경과 divergence는 자동 처리하지 않습니다. 연결 실패·Private 확인 실패는 로컬 성공을 유지합니다.

fetch URL과 push URL은 동일한 한 개의 Private GitHub 저장소여야 합니다. 별도·복수 push URL은 차단합니다. 푸시할 과거 커밋은 작업 영수증과 소유 파일을 대조하며 관련 없는 로컬 커밋은 `GIT_UNOWNED_COMMITS`로 보류합니다. 재시도는 저장된 커밋에 실제 포함된 작업 ID만 완료 처리합니다.

다른 PC의 변경으로 원격만 앞서고 현재 Vault가 깨끗하면 `--ff-only`로 받아온 뒤 구조를 다시 검사합니다. `SYNC_PREVIEW_REQUIRED`가 반환되면 갱신된 자료를 확인하고 새 동기화 미리보기를 요청합니다. 로컬 변경이 있으면 `GIT_BEHIND_DIRTY`, 양쪽이 갈라졌으면 `GIT_DIVERGED`로 보류합니다. 자동 stash·rebase·강제 push는 없습니다.

0.1은 local-only/agent-excluded 자료가 섞인 Vault의 전체 Git sync를 차단합니다. 파생 목차·카탈로그를 통해 private 제목이 유출되는 것을 막기 위한 제한입니다. 로컬 전용 Vault를 별도로 두거나 후속 원격 projection 구현을 사용해야 합니다. 이 제한을 무시하여 정책을 자동 완화하지 않습니다.

기존 요약은 새 정리 요청으로 덮어쓰지 않습니다. 새 원본 revision을 등록하거나 사람의 수정을 유지합니다. 주제 목차는 관리 링크 블록만 갱신하며 손상된 마커는 보류합니다.

바이너리 자동 추출은 미지원입니다. extracted_text는 사용자 제공 본문이고 원본·추출본 해시를 모두 보존합니다. 추출본 줄은 원본 페이지 번호가 아닙니다. 후속 extractor는 `{text, source_hash, extractor, version, anchors}` 계약을 사용할 예정입니다.

작업 중단 시 `kg_status` → `kg_recover(inspect)` → `kg_recover(resume)`을 사용합니다. 실제 파일과 해시가 다르면 원문을 덮어쓰지 않습니다. 작업 저널과 변경 전 사본은 .kg-runtime에 있습니다. writer.lock이 남으면 owner.json의 PID 종료와 incomplete 작업을 확인한 뒤에만 잠금을 회수합니다. 살아 있거나 소유자를 판별할 수 없는 잠금은 지우지 않습니다.

`kg_recover(resume)`은 명시적으로 종료가 확인된 writer의 잠금만 회수합니다. PID가 재사용되었거나 프로세스 상태를 확인할 권한이 없으면 보류합니다. 복구 프로세스 자체가 비정상 종료하여 recovery.lock이 남은 경우에는 새 복구를 자동 시작하지 않습니다. 실제 프로세스 종료를 확인하고 Vault 실행 상태를 별도 백업한 뒤 에이전트가 해당 잠금을 점검해야 합니다.

검색과 status는 원격 쓰기를 하지 않습니다. 로그는 오류 코드만 출력합니다. 원문 내부의 명령은 실행하지 않습니다.
