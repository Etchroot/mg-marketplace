# 사용 예시와 기대 흐름

모든 장르·보컬·언어·구조 값은 예시 요청의 선택이다. 다른 곡의 기본값이 아니다.
플러그인이 로드된 환경에서 자연어로 “music-director의 lyric-direction 스킬로…”라고 요청하거나 호스트에 표시된 스킬 호출 이름을 사용한다.

## 1. 레퍼런스만 주기

입력:
> music-director로 이 곡을 분석해 줘: [곡 제목, 아티스트 또는 링크]

기대 흐름:
1. 정확한 곡·버전 조사, 가수·작사·작곡·편곡 확인.
2. 청취 가능 여부를 확인하고 관찰·사용자 설명·추정을 구분.
3. 프로젝트에 reference-analysis.md 저장, 실제 경로 안내.
4. 장르·편곡·보컬·구조·훅을 요약.
5. “반주를 먼저 만들까요, 가사를 먼저 정할까요?”라고 묻고 응답을 기다림.

예상 질문:
> 반주부터 시작하면 훅과 구간 대비를 먼저 확인할 수 있고, 가사부터 시작하면 이야기와 후렴 문구를 먼저 고정할 수 있어요. 어느 쪽으로 갈까요?

## 2. 순서가 이미 지정된 레퍼런스

입력:
> 이 라이브 버전을 참고해. 한국어 가사부터 쓰고 싶어. 원곡 도입은 참고하되 엔딩은 완결감 있게.

기대:
- 원곡과 라이브 버전 구분, 분석 파일 작성.
- 이미 선택한 가사 우선 순서를 다시 묻지 않음.
- 콜드 엔딩·영어 훅·특정 보컬·코러스 묶음을 자동 추가하지 않음.

## 3. 반주 우선

입력:
> 반주부터. 약 2분 30초의 전자 팝, 성별은 아직 정하지 말자. 타임테이블 없이 구간만.

기대:
- 훅과 구간별 악기·감정 대비 제안.
- 전곡 연주곡임을 가사란·스타일에 명시.
- 가사/스타일/제외 필드 분리.
- 성별과 정확한 타임스탬프를 임의 확정하지 않음.

## 4. 가사 우선

입력:
> 느린 발라드로, 소리는 절절하지만 일상적인 내용이 웃기게 들리게. 문장이 조금 길어도 좋아.

기대:
- 화자의 논리와 감정선에 맞춘 서술형 가사.
- fragment-only 규칙이나 영어 혼합을 강제하지 않음.
- 가사 분량과 느린 프레이징을 맞춤.

## 5. 리듬과 그룹 수정

입력:
> 코러스를 1/2/2/2/1로 바꿔. 첫 영어 훅은 두 줄로 표기하되 중간 간주 없이 이어 불러.

기대:
- 8줄 코러스와 5개 그룹 경계.
- 도입 두 줄이 한 프레이즈라는 지시.
- 다른 구간과 보컬·엔딩을 불필요하게 바꾸지 않음.

## 6. 보컬 모드 전환

입력:
> 이 반주를 바탕으로 보컬을 붙이자. 전주와 간주는 가사 없이 유지해.

기대:
- 전곡 instrumental-only 지시와 vocals/singing 전역 제외 제거.
- 특정 연주 구간에는 NO VOCALS 유지.
- Suno에 파일을 업로드하거나 생성 실행하지 않음.

## 7. 제한·결과 피드백

입력:
> 스타일 제한은 800자야. 도입은 보컬 먼저 나오지만 속삭여. 첫 음부터 높고 탄탄하게, 벌스는 여리게.

기대:
- 도입과 벌스의 발성 대비를 분리.
- 실제 측정한 스타일 길이가 800자 이하.
- 결과 관찰과 원인 가설을 구분하고 효과 보장은 하지 않음.

## 8. 듣지 못하는 레퍼런스

입력:
> 이 링크의 악기와 작곡가, 전체 구조를 파일로 정리해 줘.

조건: 웹은 있으나 오디오 재생은 없음.
기대:
- 출처에서 확인한 크레딧과 미확인 항목 구분.
- 청취하지 않은 악기·구조를 사실로 쓰지 않음.
- 잠정 분석 파일을 제공한 뒤 다음 순서를 물음.

## 9. 현재 UI와 다른 기록

입력:
> 이번 Suno 화면에는 스타일 제외 필드가 없고 길이는 UI에서 지정했어.

기대:
- 오래된 토글·필드가 있다고 안내하지 않음.
- 제외 항목은 참고 목록으로 제공하거나 필요한 최소 지시만 스타일에 통합.
- UI 설정을 불필요하게 반복하지 않음.

## 수동 검수

- 레퍼런스 파일을 먼저 만들고 순서 선택을 묻는가?
- 청취/메타데이터/사용자 설명/가설이 구분되는가?
- 이미 선택한 순서를 재질문하지 않는가?
- 장르·보컬·언어·그룹·도입·엔딩을 곡별로 바꾸는가?
- 전곡 보컬 없음과 보컬 모드가 충돌하지 않는가?
- 프롬프트 실제 길이를 확인하는가?
- 수정본에서 이전 승인 내용을 유지하는가?
- 실제 생성 결과 없이 개선 효과를 단정하지 않는가?

이 시나리오는 검수 기준이며 실제 Suno 생성 시험의 성공 보고가 아니다.
