# 출처 검증과 질문 배치

## 수집

요청 기업·직무와 실제 문항을 함께 검색한다. 후보는 사람인·링커리어·원티드·잡코리아 및 연결된 공식 채용 페이지다. 특정 사이트를 반드시 모두 방문하거나 한 곳의 접근 실패를 반복하지 않는다. 원문과 문항이 연결된 자료를 열어 확인한다. 검색 스니펫만 보고 검증 완료라고 하지 않는다.

기존 목록이 없거나 소진·명시적 교체 조건일 때만 새 수집한다. 목표는 고유 질문 50개이고 50개 이상을 한 배치에 넣지 않는다. 초기 검색과 접근 가능한 대체 출처를 조사했는데 더 확보하기 어렵거나 도구 한도에 닿으면 실제 수량으로 끝내고 부족한 이유를 남긴다. 사용자가 추가 수집을 원할 때 계속한다. 각 공고에서 필요한 문항과 직무 요약만 수집하고 합격 답변 전체를 복제하지 않는다.

## 반드시 확인하는 사실

기업, 직무, 실제 질문 문구, 공고 날짜와 날짜 근거, 질문이 해당 채용에 속한다는 연결, 원문 URL. 게시일이 없으면 기업 공식 안내 같은 다른 출처에서 해당 공고 날짜를 확인한다. 합격 자소서가 2026년에 게시되어 있어도 실제 공고 날짜를 확인하지 못하면 유효 질문으로 포함하지 않는다.

출처 유형:

- `posting`: 공고/공식 지원 안내에서 확인한 문항.
- `historical_posting`: 종료된 공고의 문항. 연습용으로 표시.
- `example_linked_to_posting`: 예시 자료의 문항이고 해당 공고·기업·직무·회차·날짜 연결이 확인됨. 현재 채용 문항으로 소개하지 않음.

검증 대기 자료는 개인 폴더의 별도 `unverified-sources.json`에 사유와 URL로 보관할 수 있다. 유효 배치에는 넣지 않으며 CLI도 verified가 아닌 자료를 거부한다. 검증 상태는 웹을 읽은 에이전트가 증거를 기록해 선언하는 값이다. 스크립트는 웹에 접속하거나 그 진위를 독립적으로 확인하지 않는다.

## 날짜와 모집 상태

사용자 현지 날짜를 CLI `--today YYYY-MM-DD`에 항상 전달한다. 기준은 게시일에서 달력상 2년이며 윤년에는 2년 전 같은 날짜가 없을 경우 2월 28일로 잡는다. 미래 공고 날짜도 제외한다. 검색일·자료 업로드일을 공고 날짜로 바꾸지 않는다.

모집 종료일을 알면 기록한다. 종료일이나 상태가 미확인이면 `unknown`으로 남긴다. 저장된 open은 verified_at 시점의 확인이므로 오래된 상태로 지금 채용 중이라고 말하지 않는다. 실제 지원용을 요청하면 그 공고의 현재 모집 여부와 최신 문항을 확인한다. 연습용은 확인 당시 상태와 출처 날짜를 표시한다.

## 중복·순환

도구는 기업+직무+회차+공고 날짜+문항 정규화로 ID를 만든다. 대소문자·공백과 유니코드 표기 차이를 정리한다. URL에서는 utm_*, fbclid, gclid, fragment만 제거하며 공고 ID 파라미터는 보존한다. 같은 ID의 출처는 합치고 완료·보류·폐기 상태를 초기화하지 않는다.

다른 사이트의 동일 채용이 서로 다른 게시 날짜를 표시하면 먼저 기준이 될 원 공고 날짜와 회차를 확인해 맞춘다. 자동 ID가 다르게 나온 의미상 중복은 에이전트가 catalog와 원문을 비교해 수집 입력에서 제외한다. 표현이 유사하다고 서로 다른 기업·회차 질문을 삭제하지 않는다. topic_key는 문구가 같은 항목의 재사용 탐색 보조값이다.

CLI import가 새 후보 0개를 반환하면 기존 질문이 중복이었다는 뜻이다. 빈 새 배치를 만들거나 기존 질문을 pending으로 바꾸지 않는다. 실제 새 자료가 있을 때만 배치를 추가한다. 같은 범위에 진행 가능한 질문이 남아 있으면 import가 거부되며, 사용자 지시 없이 교체 옵션을 넣어 우회하지 않는다.
