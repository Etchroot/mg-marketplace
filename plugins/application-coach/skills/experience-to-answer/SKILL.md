# Experience to Answer

사용자가 말한 경험을 문항의 답변으로 구체화한다. 활동 나열이나 "책임감이 있다" 같은 성격 선언에서 끝내지 말고, **왜 그렇게 판단하고 행동했는지**와 그 선택에서 드러난 가치관을 연결한다. 출발 자료는 이번 사용자의 진술과 해당 사용자의 경험 파일이다. 패키지의 공개 사례를 다른 사용자의 경험으로 가져오지 않는다.

## 다섯 항목으로 정리

| 항목 | 정리할 내용 | 부족할 때 묻는 질문 예시 |
| --- | --- | --- |
| 상황 | 당시 맥락·목표·제약과 문제가 된 지점 | "그때 어떤 상태였고 무엇이 막혀 있었나요?" |
| 문제에 대한 판단 | 문제의 본질에 대한 해석, 고려한 대안, 선택 이유 | "다른 방법도 있었을 텐데 왜 이 방법을 선택했나요?" |
| 행동 | 본인이 맡아 실제 실행한 일과 팀이 한 일의 구분 | "그중 직접 한 일은 무엇이고 어떻게 진행했나요?" |
| 결과 | 확인된 변화·완성물·성과·실패와 관찰 근거 | "그 행동 이후 실제로 달라졌다고 확인한 것은 무엇인가요?" |
| 경험으로 드러난 가치관 | 판단·행동에서 드러난 기준과 앞으로도 적용할 이유 | "이 선택을 보면 본인은 무엇을 더 중요하게 여겼다고 생각하나요?" |

다섯 항목은 작성 가능 여부를 판단하는 기준이며 매번 다섯 질문을 순서대로 묻는 설문이 아니다. 이미 확보한 항목은 재질문하지 않는다. 질문마다 답변을 다섯 소제목으로 내야 한다는 뜻도 아니다. 문항·분량에 맞게 연결된 문단으로 작성한다.

## 대화와 종료 판단

1. 현재 문항과 기존 인터뷰·경험 기록을 읽는다. 다섯 항목을 확인됨 / 부족함 / 미확인으로 잠정 정리한다. 사용자 진술과 에이전트의 해석을 구분한다.
2. 본문에 필요한 빈 항목 중 핵심 한두 가지에 대해서만 후속 질문한다. 기억을 떠올리도록 장면을 좁히되 예시를 실제 경험으로 채택하지 않는다.
3. **다섯 항목을 근거 있게 작성할 수 있고, 서로 연결되며, 문항에 답할 수 있으면 추가 질문을 멈춘다.** 정확한 기술 버전·수치·날짜가 답변에 필요하지 않으면 더 캐묻지 않는다. 가치관은 사용자의 선택에서 확인되는 기준으로 표현하며 교훈을 임의로 붙이지 않는다.
4. 가치관을 말하지 않았지만 행동에서 해석할 여지가 있으면 잠정 해석으로 제안하고, 그 해석이 맞는지 한 번 확인한다. 본인의 말로 확인하기 전 강한 성격·가치관 선언을 완성된 사실로 저장하지 않는다.
5. 사용자가 중단을 요청하면 즉시 멈춘다. 내용이 부족하면 확인된 사실만 초안으로 쓰고 빈 항목을 별도로 남긴다. 보류나 다른 경험으로 전환할 수 있다.

지원 동기·직무 관심처럼 사건 중심이 아닌 문항은 상황을 관심 형성 맥락, 판단을 직무 선택 이유, 행동을 실제 탐색·준비, 결과를 변화·확인한 점, 가치관을 선택 기준으로 해석할 수 있다. 존재하지 않는 프로젝트나 성과를 만들어 다섯 칸을 채우지 않는다.

## 답변 작성

문항을 다시 읽고 필요한 항목의 비중을 결정한다. 상황을 길게 설명하기보다 판단과 행동의 연결을 드러내고, 결과 다음에는 그 행동에서 확인되는 가치관을 붙인다. 팀 전체의 성과를 본인 단독 성과로 바꾸거나 배우지 않은 교훈·숫자를 추가하지 않는다. "내 역할이 끝났는가"와 "서비스가 완성됐는가" 같은 특정 사례의 기준을 모든 경험에 적용하지 않는다.

새 답변은 사용자가 확인한 사실에 근거해 작성하고 정확한 길이를 검사한다. 기존 완성 자소서 정리 요청은 **본문 문구·순서·문단을 보존**하고 구조화 자료만 옆에 만든다. 형식 정리와 사실·문장 수정을 구분한다. 사용자가 실제 본문 수정을 요청했을 때만 새 버전으로 작성하며 원본을 유지한다.

## 저장과 재사용

일반 인터뷰 결과는 [데이터 형식](../experience-interview/references/data-format.md)의 개인 저장 절차를 따른다. 경험 카드에 situation, judgment, actions, result, values를 기록하고, 별도로 learning(사용자가 말한 배운 점), evidence, unknowns를 남긴다. judgment와 values는 기존 CLI가 보존할 수 있는 추가 필드다. 문서에서 가져온 내용은 제공된 문서의 근거이지 실제 인터뷰 진술을 직접 확인한 것이라고 하지 않는다.

공개 저장소 밖의 개인 폴더에 인터뷰·답변·경험을 저장하고 성공한 경로를 알린다. 사용자가 특정 자료의 공개 업로드를 명시적으로 요청한 경우에는 그 지정 자료만 별도의 공개 사례 폴더로 정리할 수 있다. 이것을 이후 개인 데이터의 자동 공개 허용으로 확대하지 않는다. 출처가 미확인인 기존 자소서를 검증된 채용 질문 50개 목록에 넣지 않는다.
